昨天 GPT-5 发布，我感觉它只是强大一些，但我很快就意识到，仅仅在聊天窗口里衡量它的能力有点一叶障目的感觉。大家比拼 benchmark 的劲头，正在分散我们的注意力。模型“更聪明一点”，能带来的改变有限，真正有突破性的应用，要靠一个更丰富、能让模型大展拳脚的 environment。

所以，现在每当有新模型发布，我都会跳过那些 benchmark，直奔开发者文档。最有价值的信号在 API 设计、成本曲线、上下文管理和 in-context capabilities 里，排行榜上的名次倒在其次。GPT-5 又成了最强模型，但我说它是分水岭，是因为它发出了迄今最清晰的信号：环境才最重要。

我说的 environment，包括代码的依赖，但远不止这些。它指的是能让模型有效完成真实世界任务的全部外部条件和机制，像一个支架，把一个强大但孤立的模型变成一个有用、可靠的 agent。

这个支架由几部分组成。首先是数据，包括第一方用户数据、领域知识和一个闭合的 feedback loop，它们提供特定的、专有的上下文，让一个通用模型用起来像是你自己的模型。然后是上下文和记忆，包括复杂的检索、会话记忆、持久的用户画像，重点是记住要紧的信息，光有一个超长的上下文窗口不够。再往外是执行和编排（execution and orchestration），也就是通过工具和 API 把模型连到真实世界的 runtime，负责拆解任务、从失败中恢复、可靠地执行。面向用户的是交互和工作流，它把模型的能力做成一个好用的工作流，让用户看得清、控制得住，还能引导和纠正 agent。最后是运行和成本，一个 environment 要在速度、并发和 token 用量上都足够高效，才做得下去。

同一个模型，放在不同的 environment 里，表现可能差出一个数量级。模型是一台强劲的发动机，environment 是那辆车，变速箱、车轮、方向盘决定了它能开到哪里、开多快。

## 开发者文档里的信号

GPT-5 这次发布，最让我兴奋的是平台本身那些不起眼的、“环境友好”的变化，那些引人注目的新功能倒在其次。先说 API，它扎实了很多：文档更清晰，参数的语义更明确，这显然是在照顾那些在上面搭复杂 orchestration 层的开发者。

智能的单位成本也在继续下降。定价档位和推理选项分得更细了，搭一个更“厚”的 environment 在经济上就更可行：你可以多做一些探索性的调用，做更复杂的缓存策略，跑更复杂的 agentic 循环，而不用担心成本失控。

另外，产品里到处是面向开发者的细节，背后是一次不小的工程和战略转向。长期以来的看法是，市场分得很清楚：Anthropic 是以开发者为中心、专心把 API 做扎实的公司，OpenAI 的长处在它庞大的消费级产品。这次发布把这条界线彻底模糊了。OpenAI 在开发者体验上下这么大功夫，等于默认了一件事：他们的消费级业务虽然规模巨大，但要做到真正的大规模，还得走 API 这条路。这多少是在用行动承认，消费级增长有它的极限，未来要靠整个开发者生态在它的平台上搭 environment。

## Cursor 和 Duolingo

coding 助手最能说明 environment 的作用。早期的代码助手只是笨拙的聊天界面，你把代码贴进去，然后请它修改。后来，像 Cursor 这样的小团队换了一种做法。他们没去造更好的模型，功夫全花在 IDE 里的 environment 上，把模型和整个项目的上下文、依赖图，以及一个紧凑的执行循环（建议 \-\> 运行 \-\> 测试 \-\> 反馈）连在一起，把简单的聊天变成了真正的协作。

现在，像 Claude Code 这样的大玩家正在抢着复制这种深度集成，但走的是别人已经蹚出来的路。这说明，当所有人都用着同样强的发动机（LLM），赢家是能围绕它造出最好的车的人。

再看 Duolingo。它的长处在它精心打磨的学习环境，AI 倒在其次：结构化的 curriculum 带你一步步往下学，一套很强的 gamification 和 retention engine 让你不断回来，还有测验和纠错组成的紧凑 feedback loop。

而我用 ChatGPT 练习语言时，体验完全不同。它是一个极其强大、灵活的对话伙伴，我可以聊任何话题，让它细细解释，还能做针对我自己的练习。但它没有 curriculum，不记得我学过什么，也不会为我的进步做长期规划。

垂直领域的 environment 很值钱。等到 Duolingo 能通过 API 接入 GPT-5 这样强的模型，它现有的 environment 就会变成一个巨大的放大器，把结构化、能激励人的框架和顶级模型流畅的对话能力结合起来。到那时，模型只是其中的一个零件，好比一颗超强的处理器，装进了一台本来就很会教人的机器。很多垂直领域都会是这个样子，最好的教育工具会是一台专门打造的“教学机器”，里面嵌着一个强大的通用模型。

## 模型层和环境层

这会自然形成行业里的分工。模型层正在商品化。几家主要玩家（OpenAI、Anthropic、Google、Meta、xAI）加上一个充满活力的开源生态，都在往同一个方向使劲，质量差距在缩小，竞争越来越多地转向价格、速度和功能选项（比如更长的上下文、更细粒度的工具调用）。

这些模型公司不太可能把所有有价值的垂直 environment 都吃下来，原因很简单。有价值的垂直领域太多了，没有哪一家公司能同时在 coding、教育、医疗、法律和金融上都做出深入的、一流的产品。而且，工程和合规的开销也不小，医疗 AI 和法律 AI 面对的工程难题和合规要求完全不同，这些都是要靠专业积累才建得起来的护城河。再说，API 本身就是一门很有吸引力的生意，模型公司卖的是“镐和铲”，整个生态的创新它都能分到好处，为了在少数几个垂直领域竞争而关掉 API，等于放弃来自其他所有领域的巨大边际收入和生态的势能。所以我认为，最后会形成一个稳定的两层结构：模型是基础设施，environment 是产品。

常见的反对意见有两种。一种认为，某家大模型公司会关掉 API，自己做垂直整合，把垂直 environment 里的价值全部拿走。我觉得这不太可能成功。竞争决定了市场上会一直有 API，一家关掉，另一家马上就会进来抢这些客户。只要还有高质量的 API 可用（一定会有），模型公司就很难打败一个在垂直领域做出了更好 environment 的公司，后者靠的是深厚的经验、专有数据和专门的工作流。

另一种认为，会出现一个通用的“Agent OS”，把所有垂直应用都吞掉。通用 OS 解决的是广度，垂直应用在深度、合规和专有数据上会一直占优。你可能会用一个通用 agent 订机票，但审法律合同、诊断病情，你会用一个专门的、值得信赖的 agent，两者会长期并存。
