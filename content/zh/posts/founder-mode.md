Airbnb 的联合创始人兼 CEO Brian Chesky 经常提倡“Founder Mode”（创始人模式），这个概念是 [Paul Graham](https://paulgraham.com/foundermode.html) 让它流行起来的。

我第一次接触这个概念就被它吸引了，可当时我把它理解得太窄。我以为它的意思无非是 hands-on 而不是 hands-off。这个理解太浅了，它背后其实是一套深得多的领导思路。我的误解来自 Graham 把 Founder Mode 和“Manager Mode”（经理人模式）做的对比：在 Manager Mode 下，领导者往后退一步，主要精力放在管人上，而不是直接参与具体的工作。hands-on 和 hands-off 这个划分看上去很直白，何况我在马斯克的管理哲学里也见过类似的原则：马斯克要求工程经理至少花 20% 的时间做实际的工程工作。我当时从中得出的结论是，领导者要贴近一线，弄清楚正在发生什么，避免“外行指挥内行”。

直到我自己在工作中碰到了带团队的难题，我对 Founder Mode 的理解才深了一层。差不多就在那段时间，我看到了 Brian Chesky 的一个访谈，它改变了我的想法。如果你管理的团队超过十个人，或者下面有好几个职能部门，我强烈建议你把这个访谈完整地看一遍，别开两倍速。

Brian 把 Founder Mode 浓缩成一句话：“卓越的领导力是在场，而不是缺席。” 乍一听，这像是 hands-on 和 hands-off 的区别，但 Brian 对 Founder Mode 的理解，比单纯了解一线情况要深刻得多。

他用一群人划船来打比方。向前划这个目标听起来很简单，可真划起来，光把目标说出来是不够的，所以划船时船头常常有一个人在实时指挥。如果领导者只给出一个宏大的愿景，然后把自主权都交给团队，结果可能是一团乱。这和很多商学院的教导正好相反，它们教的是：“招最优秀的人，让他们来做决定。”Brian 讲到，在 Airbnb，不同团队朝着同一个大目标努力，可自主权太大，最后常常技术栈、产品设计和流程都各不相同，彼此接不上，实际上成了几个各自独立的组织。我自己也遇到过一模一样的问题。

回到划船的比喻。就算所有人都同意往“北”划，也可能有人以每秒两桨的速度往东北偏了 15%，另一些人以每秒三桨的速度往西北偏了 10%。每个人都很卖力，也都朝着同一个目标，可船往前走的效率很低。从物理学的角度看，推船前进的合力被削弱了。

这正是 Founder Mode 起作用的地方。Brian 举的典型例子是乔布斯。乔布斯不会简单地把问题交下去，然后指望团队自己解决。他会扎进最重要的那些项目的细节里，和团队一起做。Founder Mode 下的领导者不会对每个问题都亲自拍板，他们和团队一起工作，保证大家的方向和公司的战略一致，这包括给出清晰的愿景、补充背景信息，以及帮各个团队把劲往一处使。这和我之前那篇[《不要把创始人捧上神坛》](https://www.hancezhang.blog/zh/posts/no-pedestals/)的观点是相通的：领导者要想清楚自己的位置，以及用什么方式对团队的贡献最大。你应该把自己定义为合作者之一，而不是独裁者。

避免 micromanagement 的诀窍，在于领导者以什么方式参与。乔布斯 2010 年在 D8 大会上谈到过这一点。他说苹果的组织方式像一家创业公司，是“地球上最大的 startup”，而团队合作靠的是“相信别人会把自己那部分做好，不用时时盯着”。

所以，Founder Mode 下领导者的职责，是让所有人朝同一个方向、用最大的力气划。你要做的是在场，让大家都对准更大的愿景，至于桨怎么握，让他们自己决定。
